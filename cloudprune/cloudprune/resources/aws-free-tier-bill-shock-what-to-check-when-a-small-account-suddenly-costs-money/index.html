The cost signal

A small AWS account can suddenly cost money because free-tier limits expired, public IPv4 addresses were allocated, storage was left behind, logs grew, or an instance kept running. CloudPrune can give small teams a read-only first scan that highlights exact resources, likely bill drivers, and safe next steps instead of asking them to hunt through every AWS console page.

Read-only evidence first, followed by owner review, rollback planning, and post-change validation.

How to verify manually

  1. Open AWS Billing and Cost Explorer to confirm the service driving the spend.
  2. Use the AWS console view for the affected service to identify candidate resources.
  3. Run a read-only AWS CLI inventory command and export the resource IDs before changing anything.
  4. Compare age, attachment, traffic, retention, and recent usage signals before deciding on cleanup.

Impact and rollback

  1. Classify whether the action can affect production traffic, data retention, compliance, or incident response.
  2. Prefer dry-run review first. For storage deletion, create or verify a snapshot/export when rollback matters.
  3. Schedule changes with an owner and a validation window. Stop if the blast radius is unclear.
  4. Keep the previous configuration or snapshot reference until post-change metrics are stable.

Questions people ask

Why did my AWS free tier account start charging me?

Common reasons include free-tier expiration, resources outside free-tier limits, running EC2 instances, allocated public IPv4 addresses, EBS volumes, snapshots, CloudWatch logs, NAT gateways, and data transfer.

What should I check first?

Start with Billing and Cost Explorer by service, then inspect EC2, EBS, Elastic IPs, snapshots, CloudWatch Logs, RDS, and any networking resources that have hourly charges.

Can CloudPrune change my AWS account?

CloudPrune onboarding is read-only. It shows evidence, savings, impact, and rollback guidance before any future controlled automation step.
